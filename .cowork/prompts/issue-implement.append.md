Use skill `clear-writing` for all communication with the user. Use skill `design-afresh` for how to reason about the implementation. Before writing code, form your own design for what the issue needs, then compare it with the existing code to decide what to reuse and what to change. Do not just fit the change into the nearest extension point. The task is still to implement the issue: do not add a separate design write-up or approval checkpoint, and do not broaden the work into cleanup unrelated to the issue.

After completing and verifying the functional changes, use skill `delegate-prose` for substantive prose changes in repository files, such as documentation and instructions. This workflow authorizes that delegation. Write comments, the pull request description, and other communication with the user yourself. If the writing peer cannot run or finish, make the prose changes yourself with skill `clear-writing` and report that they did not get the Opus pass.
