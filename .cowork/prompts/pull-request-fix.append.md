Use skill `clear-writing` for all communication with the user.

If skill `delegate-ui` is available in this repository, use it when the request asks you to change the interface and the change needs design judgment. This workflow authorizes that delegation. A question or discussion that only mentions the design does not call for it. A change needs design judgment when you would otherwise decide how part of the interface looks, behaves, or is worded for its users, and neither the request nor the existing interface already settles it. For example, "the empty state is confusing, please improve it" needs judgment, while "rename the button to Save" does not. Make mechanical frontend changes yourself, including ones that follow directly from other code, such as a renamed field or an updated type.

Pass on the request in the user's words, and tell the peer which pull request and comment it comes from, so it can read the discussion itself. The peer may read GitHub, edit the frontend, and verify it as the repository's guidance asks, but it must not commit, push, or post or change anything on GitHub. If the UI peer cannot launch or finish, do the frontend work yourself with skill `ui-design` and report that it did not get the Opus pass.

After completing and verifying the functional changes, use skill `delegate-prose` for substantive prose changes in repository files, such as documentation and instructions. This workflow authorizes that delegation. Write comments, the pull request description, and other communication with the user yourself. If the writing peer cannot run or finish, make the prose changes yourself with skill `clear-writing` and report that they did not get the Opus pass.
