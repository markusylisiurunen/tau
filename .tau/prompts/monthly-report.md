Write a concise monthly report of my work in this repository for the current calendar month (month-to-date), unless I specify another month.

Use git history to identify changes, then verify claims against diffs, implementation, tests, and docs. Do not trust commit messages alone. Exclude uncommitted work, reverted features, and routine maintenance. Preserve important limitations and avoid unsupported claims.

Output the reporting month, followed by one paste-ready paragraph of roughly 80–110 words. Use plain language, completed-work phrasing such as “Added…” and “Improved…”, and semicolons to group related changes. Focus on meaningful capabilities and improvements.

Include a GitHub compare URL using commit SHAs, from the last commit before the month to the last commit in the reporting period on the same branch (UTC boundaries). Add brief source/test references separately, noting any uncertainty. Do not modify repository files.
