---
label: "write a monthly report"
---

Write a concise monthly report of my work in this repository. Cover the current calendar month up to today, unless I name another month.

Write for readers who want to know what I built and why it matters, and who will not read the code. Include the work that is interesting to them. Describe it so that the full scope and value of the work come through, and do not make it sound smaller than it was. Do not exaggerate either.

Find the changes in the git history, then check each claim against the diffs, implementation, tests, and docs. Commit messages alone are not enough evidence. Leave out uncommitted work, reverted features, and routine maintenance. Keep important limitations in the report, and make no claim you cannot support.

Start the output with the reporting month. Follow it with one paragraph of about 80-110 words that I can paste as is. Write in plain language, describe completed work with phrasing such as “Added…” and “Improved…”, and use semicolons to group related changes. Focus on new capabilities and notable improvements.

Include a GitHub compare URL built from commit SHAs. It should run from the last commit before the month to the last commit in the reporting period, on the same branch, with month boundaries in UTC. If the period has no commits, or there is no earlier commit to compare from, explain this instead of inventing a URL. After the paragraph, list brief references to the sources and tests you used, and note any uncertainty.
